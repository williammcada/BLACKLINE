# BLACKLINE v0.1.0-alpha.1 — driving proof

**Scope:** Milestone A of the accepted v0.1.0 design, authorized by “proceed” on 2026-10-01. This document makes the first deliverable concrete; it does not introduce a new game or replace the full design.

**Product identity:** MathQuest cartridge. This milestone implements its mini-game and a standalone test harness, not a separate standalone product.

## Goal

Prove that entering a tight bend, braking, straightening and accelerating into a ramp is enjoyable and readable. Complete this before developing enemy AI or the five-minute course.

## Playable content

One fixed test strip, targeting a 60–90 second successful first drive, contains a gentle introduction, alternating tight bends, one crest, a recovery straight, one marked ramp across a gap and a short finish straight. Keep the hard 300-active-second ceiling. A clear finish ends the prototype early.

Use authored distance markers, not elapsed-time scenery changes. Fit jump geometry to the same simulation units as vehicle speed. The prototype ramp has equal-height takeoff and landing to make the boundary behavior inspectable.

Include automatic acceleration, left/right steering, brake/drift and rechargeable boost. Use the full spec’s initial tuning values. Enforce brake priority, no boost consumption in the air, no cooldown/time advance while paused and no randomized loss of grip. Integrity starts at 100; barrier collisions and missed jumps have clear consequences. Show speed, integrity, boost and progress.

## Presentation

Use original preliminary art drawn as code-native canvas shapes/pixel sprites: layered industrial skyline, animated road markings, barriers, ramp chevrons and a recognizable car with braking/steering/boost poses. This is a handling prototype, not final art approval.

Provide basic engine, braking, impact and landing sounds plus a short original synth loop with independent music/SFX controls. Audio begins with Play, pauses safely and never duplicates on retry. Keep visible cues sufficient when muted. Include reduced motion from the beginning.

Show BLACKLINE: Last Exit, v0.1.0-alpha.1 and A WILLIAM MCADA PRODUCT. The menu must explicitly say Driving prototype. Do not imply that missing pursuers are implemented.

## States and inputs

Title, countdown, running, paused and result. Results distinguish finish, destroyed, jump too slow, missed landing and timeout. Play/Retry reset all volatile round state. Interruption clears input and pauses the simulation. Resume requires deliberate action and fresh input.

Desktop uses arrows/A-D, Down/S to brake, Space for boost and Escape/P to pause. Touch uses adjacent left/right buttons and separate Brake/Boost buttons. Support simultaneous controls and both finger-release orders. Rotation to portrait pauses; landscape return does not resume by itself.

## Source and build shape

Plain JavaScript source with separate simulation, track, projection, input, audio and UI concerns; deterministic 60 Hz update and capped catch-up. A build script creates one HTML artifact using embedded code/assets. No external runtime dependency or persistent state. Keep development-only test hooks out of the shipped interface.

Reserve a small local lifecycle boundary for later host integration; do not claim that its proposed API matches the current Math Arcade host. Enemy AI, math, narratives, account systems, storage, analytics and deployment infrastructure are outside this milestone.

## Required verification

| Scenario | Acceptance |
| --- | --- |
| Bend entry | Braking reduces outward drift; modest overspeed is recoverable; alternating bends require real steering |
| Ramp success | A centered car at the computed safe speed lands without boost |
| Ramp failure | Too-slow and misaligned approaches produce the matching failure reason |
| Swept triggers | A maximum-speed step cannot skip takeoff, landing or finish |
| Collision hold | Sustained barrier contact follows the damage interval, not frame-rate damage |
| Pause and stall | Time, physics and charge do not advance invisibly |
| Retry | Integrity, speed, position, charge, timer, input and audio reset; one result per round |
| Input interruption | Multi-touch, cancellation, drag-outside, blur, hide and rotation neutralize controls |
| Viewport | Controls, HUD and touch hit areas survive browser-bar changes and rotation |
| Native UI | Long-press gameplay/HUD/controls does not produce disruptive selection or menus |
| Packaging | Offline desktop artifact loads with no missing network assets; version matches source |

All checks start Not run. Record automated/browser-emulated evidence separately from physical iPhone/iPad evidence. Do not certify mobile fixes from desktop emulation. Observed disruptive input, viewport and native-menu defects block release on the affected target.

## Checkpoint and handoff

Preserve source with a meaningful implementation checkpoint before extended verification. Fix concrete failures and record the exact tested candidate. Package that candidate without adding features. Preserve a recovery copy independently of whether deployment succeeds.

The owner then evaluates turning, speed, jump readability and excitement. Only after that handling review should Milestone B add lethal pursuit. First-artifact delivery does not imply approval of the final course or completion of the broader cartridge.
